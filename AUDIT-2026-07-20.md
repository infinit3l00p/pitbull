# PITBULL Full Audit — 2026-07-20 19:00 GMT+1

## Executive Summary

PITBULL is **partially functional**. The backend (port 8001) and frontend (port 5174) are running, and most API endpoints respond. However, there are **multiple critical issues** affecting reliability, security, and functionality.

---

## 🔴 CRITICAL Issues

### 1. Neo4j Docker Container NOT Auto-Starting
- **Neo4j** runs in Docker (`attacksurface-neo4j`, image `neo4j:5.15.0`)
- Docker restart policy is set to `no` — container won't auto-start on reboot
- The container was down, causing **all Neo4j-dependent endpoints to return 500**
- It started during this audit (docker-proxy appeared on port 7687)
- **Fix:** `docker update --restart unless-stopped attacksurface-neo4j`

### 2. Stale Backend Process (No Auto-Reload)
- Backend process (PID 8898) started **July 17** — 3 days ago
- Code files modified **July 20** — but uvicorn runs WITHOUT `--reload`
- 5 stale `.pyc` files in `__pycache__/` (older than source)
- The running server may be using outdated code for some modules
- **Fix:** Restart the pitbull systemd service after code changes, or add `--reload` for dev

### 3. Stale Frontend Build
- `frontend/dist/` built at 18:09 but source files modified up to 19:48
- The served frontend is **outdated** — newer code in `App.tsx`, `Chat.tsx`, `Explore.tsx`, `Overview.tsx`, `Settings.tsx` not in build
- **Fix:** Rebuild frontend: `cd frontend && npm run build`

### 4. No .gitignore — Secrets at Risk
- No `.gitignore` file exists in the PITBULL repo
- `.env` file contains Neo4j password and API key — **could be committed to git**
- Currently not in git history (lucky), but no protection
- **Fix:** Create `.gitignore` with `.env`, `__pycache__/`, `node_modules/`, `dist/`, `venv/`

## 🟠 HIGH Issues

### 5. Tor SOCKS Not Working
- Tor service is running (port 9050/9051 listening)
- Tor SOCKS5 proxy **times out** when connecting through it
- Tor logs show: "We tried for 15 seconds to connect... Retrying on a new circuit"
- Affects: `/api/v1/onion/discover`, `/api/v1/onion/crawl`, `/api/v1/onion/classify`, `/api/v1/onion/extract`, `/api/v1/relays`, `/api/v1/tor/new-circuit`
- **Fix:** Check Tor circuit health, restart Tor, or investigate network connectivity to Tor exits

### 6. External API Timeouts (No Timeout Handling)
- `/api/v1/wayback/snapshots/{domain}` — hangs indefinitely (web.archive.org)
- `/api/v1/onion/discover` — hangs (Tor dependency)
- `/api/v1/relays` — hangs (Tor dependency)
- No request-level timeout in the collectors — a single slow external API blocks the uvicorn worker
- **Fix:** Add `timeout` parameter to all `httpx.AsyncClient` calls in collectors

### 7. Shodan API Key Not Set
- `PITBULL_SHODAN_API_KEY` environment variable not configured
- `/api/v1/shodan/info` returns `{"error":"no_api_key"}`
- Shodan host search and batch lookup won't work
- **Fix:** `echo 'PITBULL_SHODAN_API_KEY=your_key' >> backend/.env` and restart

### 8. Backend Bound to 0.0.0.0
- Backend listens on all interfaces (`--host 0.0.0.0`)
- Hardcoded API key in config: `pitbull-explorer-dev-key-2026`
- Anyone on the network can access the API with this known key
- **Fix:** Bind to `127.0.0.1` for local use, or use a proper API key for production

### 9. Debug Mode Enabled in Config
- `PITBULL_DEBUG=true` in `.env`
- Exposes verbose debug logs including Neo4j connection details
- **Fix:** Set to `false` for production use

## 🟡 MEDIUM Issues

### 10. Version Number Stale
- `config.py` says `app_version: str = "0.0.1"` but we're at Phase 7
- `frontend/package.json` says `0.1.0`
- Inconsistent versioning across the app
- **Fix:** Update to `0.7.0` in config.py and package.json

### 11. Redundant Vite Dev Server
- Frontend Vite dev server (port 5174) is running alongside the built `dist/` served by backend (port 8001)
- The Vite dev server consumes ~150MB RAM unnecessarily
- Backend already serves the built frontend on port 8001
- **Fix:** Stop the Vite dev server if not actively developing: `kill 9010 9024`

### 12. OpenAPI Spec Shows Double-Prefixed Paths
- Routers with their own `prefix` AND routes that include the prefix in their path
- Example: `explore.router` has `prefix="/explore"` and routes like `/explore/start`
- OpenAPI spec shows `/api/v1/explore/explore/start` but actual serving works at `/api/v1/explore/start`
- Cosmetic issue only — doesn't affect functionality
- **Fix:** Remove the prefix from individual route paths, or remove the router prefix

### 13. ATTandCK-Surface App Also Running
- Another app (`ATTandCK-Surface`) is running on port 8000 (two processes on 127.0.0.1 and 0.0.0.0)
- Consumes ~220MB combined RAM
- Memory pressure: 10G/14G used, only 629M free
- **Fix:** Stop if not needed: `systemctl stop att-and-ck-surface` (or similar)

### 14. Git Working Tree Dirty
- 21 files changed, 2403 insertions, 2053 deletions
- Uncommitted changes in `explore.py`, `exploit.py`, `exploit_experts.py`, `main.py`, `App.tsx`, `api.ts`, `Exploit.tsx`
- **Fix:** Commit changes or stash them
